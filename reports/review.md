# Повторная проверка

## Что проверяю

- Полный контекст не пересекает base и отложенные части; cold-тексты целиком исключены из base.
- Тексты rank_train/dev/test не пересекаются между собой; truth соответствует сохраненным парам.
- У кандидатов допустимые индексы, нет повторов query/source/item, ранги положительные.
- Признаки модели не содержат query_id, item_id, target, split и regime.
- Для новых dev-экспериментов загружаю fusion.cbm, а не финальную модель, обученную в том числе на dev.
- Перед новым ответом полностью воспроизвожу старый и сравниваю все строки.
- CSV проверяю по исходным benchmark ID, а не только по длине строк.

Результаты проверок -- в `outputs/validation`. После правки комментариев сравниваю AST:
расчетная логика прежних моделей остается той же. Исправление проверки ноутбуков отдельно:
новый файл больше не может молча выпасть из проверки из-за короткого списка префиксов.

## Что нельзя доказать этими проверками

Временной утечки нельзя исключить без дат: метаданные объявлений представлены одним снимком.
Warm допускает известный выбор item в другом контексте. Это заявленное свойство протокола;
для него отдельно есть срез новых пар.
Общий каталог доступен без меток, но составлен в том числе из выбранных train-объявлений.
Локальная задача отличается от скрытого benchmark и не является его точной копией.

Исходный holdout оценивает выбор, сделанный до его открытия. Новые эксперименты из `07`
провожу уже после знакомства с этим результатом; не называю их новой независимой проверкой.
В финальном refit использую все отложенные метки. Его нельзя заново оценивать на тех же частях.

Обозначение OOF в коде относится к кандидатам, полученным без своих полных контекстов.
Это одно разбиение base/held, а не полноценная перекрестная k-fold валидация.
Статическая проверка имен ноутбуков не заменяет исполнение всех восьми файлов в одном kernel.
Каждый выполнен в отдельном kernel; для полного запуска этот режим предпочтителен по памяти.

Решение готово к отправке и воспроизводимому локальному запуску. Нагрузочный тест сервиса,
мониторинг и обновление индексов здесь не реализованы: это исследовательский репозиторий, не готовый production-сервис.

## Исправления при переносе в ноутбуки

1. В новом признаке согласия источников обнаружил зависимость знаменателя от колонок batch.
   В локальной проверке history_context отсутствует, на benchmark появляется. Фиксирую список
   каналов по обучению и проверяю инвариантность при добавлении лишнего канала.
2. Старый скрипт скачивания каждый раз запрашивал актуальный SHA модели. Теперь 12 читает
   сохраненный revision. Это устраняет возможность незаметно воспроизвести эксперимент с другими весами.
3. Убрал динамическую генерацию Markdown-выводов и запись отчета EDA из вычислительной ячейки.
   Выводы редактирую явно после анализа, как в референсном репозитории.
4. Общие функции перенес в common.ipynb; повторно запускаю 00--08 и проверки без src/scripts.

Формулу Recall@50 не менял: ошибки в ней повторная проверка не выявила.
Не приписываю этим исправлениям прирост официального score без новой отправки.
