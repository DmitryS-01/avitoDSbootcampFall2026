# Avito -- поиск кандидатов для услуг

Для каждого запроса ищу до 50 объявлений из benchmark_items. Метрика -- macro Recall@50.
Вся реализация находится в ноутбуках. Seed -- **143**.

Первая отправка дала **0.821574** по сообщению о результате платформы.
Исходное решение сохранено в коммите `a7c684d`, ответ -- `outputs/submissions/answer.csv`.
Разметка benchmark недоступна; локальные метрики храню отдельно.

## Как устроено решение

Lexical, история и E5 находят кандидатов. RRF объединяет выдачи в пул до 400 объявлений.
CatBoost по признакам пары оставляет 50. Глобальные и локальные источники работают вместе:
жесткое совпадение локации потеряло бы часть положительных примеров.

Основной вариант использует 80 признаков. Отдельно проверил 21 дополнительный признак,
линейную модель, групповое ранжирование, небольшую MLP и ансамбли. Не включаю новую модель
в решение только потому, что она сложнее: сравниваю с исходным CatBoost на одном dev.

## Структура

```text
notebooks/       весь код, эксперименты и выводы
  common.ipynb   общие функции; остальные ноутбуки подключают его сами
  00--01         EDA, признаки и разбиения
  02--05         baseline, hybrid, E5 и CatBoost
  06             исходный answer.csv
  07             размер пула и примесь RRF
  08             дополнительные признаки и EDA
  09             сравнение семейств моделей
  10             blending, stacking и новые ответы
  11             тесты, утечки и формат CSV
  12             подготовка весов и упаковка
reports/         методология, результаты и ограничения
dataset/         три исходных Parquet, без изменений
outputs/
  figures/       графики
  validation/    таблицы метрик и проверки
  submissions/   файлы для отправки
  models/        конфигурации и локальные веса
  cache/         восстановимые индексы, embeddings и кандидаты
```

В common оставил только повторяемые функции. Загрузка данных, выбор параметров, обучение
и выводы видны в основных ноутбуках. Выводы записаны обычными Markdown-ячейками;
код не переписывает текст отчетов. Нет отдельного сервиса или своего фреймворка экспериментов.

## Запуск

Использую Python 3.12. Для полного каталога желательно 32 GB RAM или больше.
E5 использует MPS/CUDA при наличии; CPU тоже поддерживается. Остальные модели обучаю локально.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export AVITO_DATA_DIR="$PWD/dataset"
jupyter lab
```

В dataset нужны train.parquet, benchmark_queries.parquet, benchmark_items.parquet.
Полный архив содержит данные и веса E5. Если весов нет, сначала выполняю раздел подготовки
весов в 12; revision зафиксирован в outputs/models/dense_manifest.json.
После скачивания обучение и поиск не требуют внешних API.

Ноутбуки 00--06 запускаю последовательно через Run All. Для дополнительных экспериментов
продолжаю 07--10, затем 11. common отдельно запускать не требуется. 12 нужен только для
подготовки весов или упаковки. При запуске отдельного позднего ноутбука нужны артефакты предыдущих.

Можно выполнить ноутбук из терминала:

```bash
jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 notebooks/00_EDA.ipynb
```

Разные префиксы исследовательских переменных уменьшают риск конфликтов имен. Общие функции
одинаковы во всех ноутбуках. Для полного прогона предпочитаю отдельные kernels: так тяжелые
матрицы предыдущего эксперимента не остаются в памяти.

После смены данных или логики признаков пересоздаю зависимые кеши. Кеши прежней модульной
версии с src не смешиваю с новой: индексы восстанавливаются в 02. Исходные CSV сохранены в Git.
requirements.lock.txt описывает использованное окружение; requirements.txt задает совместимые диапазоны.

## Валидация

Дубликаты пары полный контекст--item удаляю до разбиения. Cold откладывает весь текст запроса,
warm -- полный контекст знакомого текста. Историю и adapter учу только на base, CatBoost -- на
отдельных кандидатах rank_train. Dev выбирает параметры. Исходный holdout был открыт после выбора:
cold **0.80754**, warm **0.81098**, по 1000 запросов.

Новые эксперименты проведены после открытия holdout; не выдаю их за новую независимую оценку.
Для stacking делю dev на calibration/comparison. Базовые модели не обучаются на их метках,
но эти запросы участвовали в прежнем выборе гиперпараметров -- это ограничение явно сохраняю.
Финальный refit использует все доступные отложенные пары; локальный score повторно ему не приписываю.
